# AI Severity Assessment and Damage Impact Analysis Subsystem

## Overview

The **AI Severity Assessment & Damage Impact Analysis** subsystem evaluates the physical severity, potential safety hazards, and public disruption caused by verified civic infrastructure defects.

> [!IMPORTANT]
> **Advisory Decision-Support Notice**:
> The severity metrics, levels, and factors generated by this module are algorithmic approximations designed strictly for **municipal prioritization and triage support**. They do **not** constitute a certified civil engineering assessment, structural safety certification, or forensic accident prediction.

---

## 1. Core Architecture

```text
Verified Complaint
       ↓
2D YOLO Detections & Bounding Boxes
       ↓
Damage Extent Geometry (Surface Area Ratio)
       ↓
Category-Specific Severity Rules & Disclaimers
       ↓
Component Risk Dimensions:
├── Safety Risk Score (0–100)
├── Infrastructure Impact Score (0–100)
├── Public Impact Score (0–100)
├── Detection Confidence (0–100)
└── Description Severity Signals (0–100)
       ↓
Multi-Factor Weighted Evidence Fusion
       ↓
Multi-Detection Saturation Aggregator
       ↓
Severity Score (0–100) & Discrete Level (LOW / MEDIUM / HIGH / CRITICAL)
```

---

## 2. Gating and Integrity Rules

1. **Verified Status Requirement**: Severity analysis is computed **only** for complaints whose status is `VERIFIED` (or explicitly approved by an administrator).
2. **Rejection Safeguard**: Complaints in `REJECTED` status cannot undergo severity analysis; API calls on rejected complaints return HTTP `400 Bad Request`.
3. **2D Bounding Box Proxy**: Bounding box geometry is treated strictly as an approximate 2D visible surface coverage ratio:
   $$\text{damage\_area\_ratio} = \frac{\text{bbox\_width} \times \text{bbox\_height}}{\text{image\_width} \times \text{image\_height}}$$
   Physical depth, hollow subsurface volumes, or structural load capacity are explicitly disclaimed.

---

## 3. Configurable Scoring Equations

All weights, thresholds, and category baselines are configured externally in `backend/config/severity.yaml`:

### Severity Thresholds
* **LOW**: $0.0 \le \text{Score} < 40.0$
* **MEDIUM**: $40.0 \le \text{Score} < 70.0$
* **HIGH**: $70.0 \le \text{Score} < 90.0$
* **CRITICAL**: $90.0 \le \text{Score} \le 100.0$

### Component Weights
$$\text{Score} = 0.20 \cdot S_{\text{damage}} + 0.10 \cdot S_{\text{conf}} + 0.30 \cdot S_{\text{safety}} + 0.20 \cdot S_{\text{infra}} + 0.20 \cdot S_{\text{public}}$$

### Multi-Detection Aggregation
When an image contains multiple defect loci (e.g. 3 potholes or pothole + garbage), scores are combined with soft-saturating diminishing marginal contributions:
$$\text{Aggregated Score} = \max(S_i) + \sum_{j \neq \text{primary}} 0.30 \times S_j \quad (\le 100.0)$$

## 4. Category-Specific Severity Rules

| Category | Safety Hazard Base | Infrastructure Base | Public Impact Base | Special Factors & Disclaimers |
|---|---|---|---|---|
| **Pothole** | 65.0 | 70.0 | 60.0 | Surface area disruption; cluster impact; disclaims depth estimation |
| **Garbage** | 40.0 | 50.0 | 65.0 | Accumulation volume; disclaims biochemical infection or disease inference |
| **Open Manhole** | 90.0 | 75.0 | 80.0 | High baseline drop hazard in public access areas; avoids assuming pedestrian presence |
| **Damaged Road** | 65.0 | 80.0 | 70.0 | Asphalt fracturing, rutting, structural degradation |
| **Broken Streetlight**| 50.0 | 60.0 | 55.0 | Nocturnal visibility hazard; avoids speculating on crime incidents |
| **Water Leakage** | 55.0 | 75.0 | 65.0 | Visible surface flooding; avoids speculating on water contamination |
| **Damaged Sidewalk**| 55.0 | 65.0 | 60.0 | Pedestrian walkway tripping proxy and accessibility hindrance |
| **Fallen Tree** | 85.0 | 75.0 | 85.0 | Thoroughfare blockage and potential utility line hazard |
| **Illegal Dumping** | 45.0 | 55.0 | 70.0 | Waste accumulation & drainage blockage; strictly non-accusatory |

## 5. REST API Endpoints

### `POST /api/ai/severity`
Executes or retrieves severity analysis for a complaint.
* **Input**:
  ```json
  {
    "complaint_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "force_recompute": false
  }
  ```
* **Output**:
  ```json
  {
    "complaint_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "severity_score": 84.2,
    "severity_level": "HIGH",
    "safety_risk_score": 88.0,
    "infrastructure_impact_score": 79.0,
    "public_impact_score": 83.0,
    "detection_analysis": [
      {
        "category": "pothole",
        "confidence": 0.91,
        "damage_extent_score": 76.0,
        "damage_area_ratio": 0.086,
        "severity_contribution": 84.2
      }
    ],
    "evidence": {
      "damage_extent": 76.0,
      "safety_risk": 88.0,
      "infrastructure_impact": 79.0,
      "public_impact": 83.0,
      "detection_confidence": 91.0,
      "text_signal": 74.0
    },
    "factors": [
      "Extensive visible road surface disruption occupying large road section.",
      "Elevated safety risk associated with pothole defect geometry."
    ],
    "explanation": [
      "Detected primary issue 'pothole' with model confidence of 91.0%.",
      "Visible damage occupies a substantial portion of the captured frame...",
      "Note: Severity score is an AI-assisted decision-support assessment..."
    ],
    "model_version": "civic_yolo_v1",
    "severity_config_version": "v1.0.0",
    "cached": false
  }
  ```

### `GET /api/ai/severity/{complaint_id}`
Retrieves stored severity results directly from `severity_analysis` table.
